# Registration Login — v4

API на NestJS, PostgreSQL и Prisma. Пароли хранятся в bcrypt, авторизация работает через JWT.

## Запуск

```bash
npm ci
npx prisma generate
npx prisma migrate deploy
npm run start:dev
```

В локальном `.env` нужны `DATABASE_URL` и `JWT_SECRET_CODE`. `PORT` необязателен, по умолчанию сервер запускается на порту 3000. Секрет JWT должен быть непустым. В окружении сервера эти значения можно задать напрямую.

## Запросы

| Метод | Путь | Доступ |
| --- | --- | --- |
| POST | `/users/register` | Без токена |
| POST | `/users/login` | Без токена |
| GET | `/users/me` | По токену |
| GET | `/users` | По токену |
| GET | `/users/:id` | По токену |
| PUT | `/users/:id` | Только свой аккаунт |
| DELETE | `/users/:id` | Только свой аккаунт |

Регистрация и обновление принимают `nickname`, `password` и необязательный целый `age` от 0. Если возраст не указан, сохраняется 0. Никнейм — от 3 до 16 символов, пароль — от 6 до 20.

Для входа передай `nickname` и `password`. В ответе придут `Account`, `access_token`, `token_type` и `expires_in`. Токен действует 3600 секунд; после истечения нужно войти снова.

В защищённых запросах передавай заголовок:

```text
Authorization: Bearer <access_token>
```

Без токена, с неверной подписью или истёкшим сроком сервер вернёт 401. Попытка изменить или удалить чужой аккаунт вернёт 403. Пароли и их хеши в ответы не попадают.

## Проверка

```bash
npm run build
npm run lint
npm test
npm run test:e2e
```

HTTP-тесты проверяют регистрацию, вход и доступ с JWT. Вместо настоящей базы в них используется память, поэтому локальные данные не меняются.
